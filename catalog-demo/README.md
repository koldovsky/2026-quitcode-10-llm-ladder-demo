# Кладівник у Claude Code: той самий скіл, що в nanoclaw

Ця папка — демо «віртуального працівника» без жодного рядка коду. Це каталог домашніх речей: де що лежить, на якій полиці, в якій коробці. Ви пишете звичайною мовою, наприклад «де лежить ліхтарик?», а Claude Code відповідає й сам змінює файли каталогу.

Усі дані в `catalog/` вигадані.

## Звідки це взялося: nanoclaw

[nanoclaw](https://github.com/nanocoai/nanoclaw) — невеликий відкритий проєкт (MIT, © 2026 Gavriel): особистий AI-асистент, який живе в месенджері. Автор курсу запускає свою копію (fork) як «кладівника» в Telegram. Як це влаштовано:

- **Один процес Node.js.** Він читає повідомлення з месенджера й кладе їх у чергу.
- **Окремий контейнер Docker на кожну групу чату.** Агент працює всередині контейнера.
- **Агент бачить лише змонтовані папки.** Змонтувати папку означає показати контейнеру одну папку з комп'ютера. Решта диска для агента не існує.
- **Усередині контейнера працює Claude Agent SDK.** Це бібліотека, на якій побудований сам Claude Code.
- **Налаштування — це скіли Claude Code, а не нові функції в коді.** Принцип nanoclaw: «Skills over features». Скіл — це файл `SKILL.md` з інструкцією для агента: коли його застосовувати й що робити.

Каталог речей у nanoclaw — це не окрема програма, а **один скіл**: `container/skills/home-catalog/SKILL.md`. Він описує, як зберігати речі (папки й Markdown-файли), як їх шукати й переносити.

## Чому той самий скіл працює у звичайному Claude Code

У контейнері nanoclaw викликає функцію `query()` з Claude Agent SDK (`container/agent-runner/src/index.ts`, рядки 416–456) з такими параметрами:

- `settingSources: ['project', 'user']` (рядок 439) — налаштування й скіли читаються з папок `.claude/`, як у Claude Code;
- `allowedTools: [..., 'Skill', ...]` (рядок 432) — агент може викликати скіли;
- `systemPrompt: { type: 'preset', preset: 'claude_code', append: … }` — системний промпт Claude Code з доданим глобальним `CLAUDE.md`. Його передають лише для неголовних груп, коли є глобальний `CLAUDE.md` (рядки 394–397, 423–424).

А `src/container-runner.ts` (рядки 130–134) копіює скіли з `container/skills/` у `.claude/skills/` кожної групи. Отже, всередині контейнера працює **той самий рушій, що й Claude Code на ноутбуці**, і скіли він шукає там само. Тому скіл можна скопіювати в `.claude/skills/` будь-якої папки, і Claude Code почне ним користуватися.

Ми лише прибрали з копії частини, які є тільки в контейнері: шлях `/workspace/catalog/` замінено на `./catalog/`, а надсилання фото в Telegram прибрано.

## Що лежить у цій папці

| Файл або папка | Що це |
|---|---|
| `.claude/skills/home-catalog/SKILL.md` | Скіл кладівника, адаптована копія з nanoclaw |
| `.claude/settings.json` | Дозволи: що агенту можна читати, змінювати й запускати |
| `CLAUDE.md` | Коротка інструкція для агента: це демо-каталог, працюй лише в `catalog/` |
| `catalog/` | Сам каталог. Контейнер (кімната, полиця, коробка) — це папка з файлом `_container.md`, річ — це файл `Назва.md` |
| `runs/2026-11-09/` | Записи справжніх прогонів 09.11.2026: запит, виклики інструментів, відповідь, тривалість |

Початковий вміст каталогу:

```
catalog/
└── Комора/
    ├── Полиця 1/   Ліхтарик, Подовжувач, Батарейки AA (8 шт.)
    └── Полиця 2/
        └── Ялинкові прикраси/   Гірлянда, Ялинкові кульки (12 шт.)
```

## Що потрібно

- Встановлений Claude Code (команда `claude`) з активною підпискою або ключем API.
- Windows PowerShell 5.1 або PowerShell 7. Команди нижче запускайте по одній.
- Git for Windows, бо скіл переносить файли командою `mv` через Bash.

## Варіант 1. Живий діалог (основний для заняття)

Відкрийте PowerShell у папці репозиторію демо й виконайте:

```powershell
cd catalog-demo
```

```powershell
claude --setting-sources project
```

`--setting-sources project` означає: брати дозволи лише з `.claude/settings.json` цієї папки, без ваших особистих налаштувань (`~/.claude/settings.json`). Без цього параметра ваші особисті дозволи додаються до дозволів проєкту (див. розділ «Межі»).

**Перший запуск:** Claude Code спитає, чи довіряєте ви цій папці. Оберіть «Yes». Лише після цього Claude Code застосовує правила `allow` з `.claude/settings.json`: читання, пошук, запис у `catalog/` і `mv` відбуваються без додаткових запитань. Усе інше Claude Code спершу запитає у вас.

Далі вводьте запити по одному:

```text
Додай на полицю 2 в коморі коробку «Зимові речі», а в неї — шапку й рукавички
```

```text
Де лежить ліхтарик?
```

```text
Перенеси подовжувач у коробку «Зимові речі»
```

Ще кілька запитів для експериментів:

```text
Що лежить у коробці «Ялинкові прикраси»?
```

```text
Зменш кількість батарейок AA на 2. Скільки залишилось?
```

**На що дивитися:**

1. Першим кроком Claude викликає інструмент **Skill** зі скілом `home-catalog`. Так агент «вмикає» інструкцію кладівника.
2. Далі агент шукає файли (Glob, Grep), створює їх (Write) або переносить (Bash `mv`).
3. Відкрийте папку `catalog/` у провіднику, VS Code або Obsidian. Нові папки й файли з'являються одразу.
4. Відкрийте будь-який створений файл, наприклад `catalog/Комора/Полиця 2/Зимові речі/Шапка.md`. Агент заповнив поля за шаблоном зі скіла: `type`, `id`, `title`, `tags`, `created_at`, `updated_at`.

## Варіант 2. Без діалогу: одна команда — одна відповідь

Режим `-p` (print) виконує один запит і завершується. Так nanoclaw і працює: повідомлення надходить, агент відповідає, контейнер завершує роботу.

Якщо ви ще не в папці `catalog-demo` (після варіанта 1 ви вже там):

```powershell
cd catalog-demo
```

```powershell
claude -p "Де лежить ліхтарик?" --setting-sources project --permission-mode dontAsk --allowedTools "Skill" "Read(./**)" "Glob" "Grep" "Edit(./catalog/**)" "Bash(mv *)" --output-format text
```

Що означають параметри:

- `-p "..."` — запит; відповідь з'явиться в консолі.
- `--setting-sources project` — брати налаштування лише з цієї папки, без ваших особистих дозволів.
- `--permission-mode dontAsk` — нічого не питати. Усе, що не дозволено явно, відхиляється.
- `--allowedTools ...` — список дозволених інструментів:
  - `Skill` — викликати скіли;
  - `Read(./**)` — читати файли лише в цій папці;
  - `Glob`, `Grep` — шукати файли й текст;
  - `Edit(./catalog/**)` — створювати й змінювати файли лише в `catalog/`. Правило `Edit` діє і на інструмент Write;
  - `Bash(mv *)` — з усіх команд Bash дозволено лише `mv`, тобто перенесення.
- `--output-format text` — звичайний текст. Варіант `--output-format json` додає службові дані: кількість кроків (`num_turns`) і вартість за тарифом API (`total_cost_usd`).

Якщо папці ще не довіряли (див. варіант 1), Claude Code виведе попередження `Ignoring 6 permissions.allow entries...`. Нічого страшного: потрібні дозволи вже передано в `--allowedTools`.

Інші запити з цього демо:

```powershell
claude -p "Додай на полицю 2 в коморі коробку «Зимові речі», а в неї — шапку й рукавички" --setting-sources project --permission-mode dontAsk --allowedTools "Skill" "Read(./**)" "Glob" "Grep" "Edit(./catalog/**)" "Bash(mv *)" --output-format text
```

```powershell
claude -p "Перенеси подовжувач у коробку «Зимові речі»" --setting-sources project --permission-mode dontAsk --allowedTools "Skill" "Read(./**)" "Glob" "Grep" "Edit(./catalog/**)" "Bash(mv *)" --output-format text
```

Назви в запитах беріть у «ялинки», а не в звичайні лапки `"..."`: Windows PowerShell 5.1 неправильно передає вкладені лапки програмам.

Якщо замість кирилиці бачите «кракозябри», виконайте один раз у цьому вікні PowerShell:

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8
```

## Межі: де тут «контейнер»?

У nanoclaw межу задає **контейнер**: агент фізично не бачить нічого, крім змонтованих папок. **На ноутбуці контейнера немає.** Claude Code працює від вашого імені й технічно може дістатися до всього диска. Тут межу задають три речі:

1. **Дозволи в `.claude/settings.json`** разом із режимом `dontAsk` або вашими відповідями «так/ні» в діалозі. Увага: Claude Code додає до них дозволи з ваших особистих налаштувань (`~/.claude/settings.json`), і вони діють у будь-якій папці. Тому демо запускаємо з `--setting-sources project`.
2. **Папка, з якої запущено `claude`.** Файли поза нею Claude Code без дозволу не читає й не змінює.
3. **Інструкції** в `CLAUDE.md` і `SKILL.md`. Це прохання до моделі, а не замок.

Що перевірено на копії цієї папки з фіктивними файлами:

| Спроба агента | Результат |
|---|---|
| Прочитати `../.env` (файл із ключами у батьківській папці) інструментом Read або командою, де шлях видно (`wc -l < ../.env`) | Відмова. Діє правило `deny`: `Read(//**/.env)` |
| Прочитати `../.env` зсередини програми, наприклад `python -c "open('../.env')…"` | **Без `--setting-sources project` спрацювало**: на ноутбуці автора особисті налаштування дозволяли `python`, а шлях усередині коду Python Claude Code не бачить. З `--setting-sources project` — відмова. Тепер ще й `deny` для `python`, `node`, `powershell`, `cat` та інших у `.claude/settings.json` |
| Прочитати будь-який інший файл у батьківській папці | Відмова: файл поза робочою папкою, а режим `dontAsk` нічого не дозволяє без правила |
| Створити файл поза `catalog/` | Відмова: дозволено лише `Edit(./catalog/**)` |
| `mv` файла з батьківської папки | Відмова: Claude Code перевіряє шляхи команди `mv` |
| `mv` файла з `catalog/` у корінь `catalog-demo/` | **Дозволено.** Правило `Bash(mv *)` обмежує команду, а не шлях |
| Змінити власні дозволи `.claude/settings.json` через Edit | Відмова. Діє правило `deny`: `Edit(./.claude/**)` |
| Перенести `.claude/settings.json` або `CLAUDE.md` у `catalog/` командою `mv` | Відмова: Claude Code звіряє шляхи `mv` з правилами `deny` для `Edit` |

Дві дрібниці, які легко пропустити:

- Окремих правил `Write(шлях)` немає: шлях для запису задає правило `Edit(шлях)`. Так попереджає сам Claude Code.
- Якщо JSON у `settings.json` зламаний, у режимі `-p` файл тихо ігнорується, і жодне правило не діє. Перевіряйте межу пробним запитом, а не на око.

**Урок із самого nanoclaw.** Головна (main) група отримує змонтованою **всю папку проєкту з правом запису** (`src/container-runner.ts`, рядки 70–76). У корені проєкту лежить `.env` із токенами. Список заборонених шаблонів (`.env`, `.ssh`, `credentials`…) у `src/mount-security.ts` діє лише для додаткових папок, а не для кореня проєкту. Документація nanoclaw (`docs/SECURITY.md`) прямо визнає: агент може знайти облікові дані через Bash або файли.

Висновок: **межа діє, лише коли агент не може її прочитати чи переписати.** Тому тут заборонено і читати `.env`, і змінювати `.claude/`, де лежать самі дозволи. І ще одне: ваші особисті дозволи діють у кожному проєкті, тож перевіряйте межу саме з тими налаштуваннями, з якими запускаєте агента.

## Як повернути каталог до початкового стану

Після демонстрації (команди працюють, коли папку вже закомічено в git), по одній:

```powershell
git checkout -- catalog
```

```powershell
git clean -fd catalog
```

Перша команда відновлює змінені й перенесені файли, друга видаляє створені під час демо.
